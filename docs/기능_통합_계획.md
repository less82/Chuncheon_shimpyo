# 기능 통합 계획 — 흩어진 춘천 버스 정보를 한 앱으로

> 계획 문서다. 현재 요구사항은 `현재/`의 네 문서이며, 이 문서는 그 위에 무엇을 더할지만 정한다.
> 구현이 끝난 항목은 이 문서가 아니라 `현재/01_제품_화면.md`에 반영한다.

## 1. 왜 하는가

춘천 버스 정보는 지금 세 곳에 흩어져 있고, 서로 링크로만 이어져 있다.

| 사이트 | 주체 | 실제로 가진 것 |
|---|---|---|
| `ccbus.co.kr` | 춘천시민버스(운수회사) | 회사소개, 요금, 분실물, 고객센터, VOC, 노선 eBook·PDF |
| `chuncheon.go.kr/traffic` | 춘천시청 | 주정차단속, 통학택시, 특별교통수단, 고령운전자 지원, 공영주차장, 교통카드 |
| `ccbus.chuncheon.go.kr` | 춘천시 BIS | 경로검색, 노선검색, 정류소검색, 운행시간표, 실시간 버스위치 |

확인된 사실: **`ccbus.co.kr`의 실시간·노선·정류소·시간표 링크는 전부 BIS로 나간다.** 회사 사이트는 조회 기능을 하나도 갖고 있지 않다. 시민은 요금을 보고, 노선을 찾고, 분실물을 신고하려면 사이트를 세 번 갈아탄다.

여기에 네 번째 조각이 있다. 춘천시 「시내(마을)버스 문의사항이 생기셨나요?」 안내문은 **어떤 민원을 누가 받는지**를 공식적으로 밝혀 놓았고, 정류장 시설 민원은 "정류소 위치와 번호를 함께 알려주면 빠르게 처리한다"고 명시한다. 우리는 그 번호를 이미 갖고 있다.

**이 앱의 통합 가치는 조회 기능을 새로 만드는 데 있지 않다. 흩어진 접점을 하나로 접고, 모든 시민 신호를 정류장 관리번호에 묶어 행정에 넘기는 데 있다.**

## 2. 원칙 (바꾸지 않는 것)

- 디자인 언어를 바꾸지 않는다. 기존 토큰·컴포넌트·간격을 그대로 쓴다.
- 첫 화면(320×461px)의 핵심 흐름에 세로 스크롤을 두지 않는다.
- 참고·안내 성격의 화면에서만 스크롤을 허용한다.
- 근거 없는 값을 만들지 않는다. 시설은 `있음/없음/미확인` 3상태를 유지한다.
- 공식 연계 전에는 `민원 접수`라고 표시하지 않는다. 접수처 **안내**까지만 한다.
- 실시간 조회 실패를 배차간격으로 대체하지 않는다.

## 3. 무엇을 만드는가

### 이번 범위 (원본 데이터가 이미 디스크에 있다)

| # | 기능 | 근거 데이터 | 상태 |
|---|---|---|---|
| A | 버스 문의처 안내 (독립 화면) | 춘천시 안내문 → `src/data/busContacts.ts` | 제보 흐름 안에만 있음 → 밖으로 꺼낸다 |
| B | 정류장 검색 (이름·번호) | `stops.json` 1,890개 | 미구현 |
| C | 노선 검색 + 경유 정류장 순서 | `routes.json` 223개 노선 (평균 72.5정류장) | **데이터만 있고 화면이 없다** |
| D | 찾기 허브 + 진입점 | — | 미구현 |

C가 특히 아깝다. `routes.json`을 만들어 놓고 `TripView`·`AppReport` 내부 계산에만 쓰고 있다. 시민이 노선을 볼 방법이 없다.

### 이번에 하지 않는 것 (근거가 없어서)

| 기능 | 막힌 이유 |
|---|---|
| 운행시간표 (첫차·막차·배차) | **원본이 없다.** `headwayMin`은 노선 수로 추정한 값이라 시간표로 쓰면 금지 규칙 위반 |
| 실시간 버스 위치 | TAGO `getRouteAcctoBusLcInfo` 필요. `TAGO_KEY` 미설정 |
| 요금안내 | 요금 원본 없음. 임의 표기 금지 |
| 분실물 접수·조회 | 접수 백엔드 필요 |
| 주정차단속, 통학택시, 특별교통수단 | 춘천시 시스템 연계 합의 필요 |

이 표는 발표에서 "현재 구현과 미구현 기능의 구분"을 말할 때 그대로 쓴다.

## 4. 화면 설계

진입점은 **홈 타일 하나만** 늘린다. 첫 화면 무스크롤을 지키기 위해서다.

```
홈 (/app)
 └ [정류장·노선 찾기] ──▶ /find   찾기 허브
                            ├ 정류장   이름·번호로 검색 → 정류장 상세
                            ├ 노선     번호로 검색 → 경유 정류장 순서
                            └ 문의처   춘천시 안내문 전체 + 바로 전화
```

- `/find` 는 세 탭을 가진 허브다. `?tab=stops|routes|contacts` 로 직접 진입할 수 있다.
- 탭 안의 목록은 스크롤을 허용한다(참고 화면).
- 정류장 상세는 기존 `StopCard` 표현을 재사용한다. 시설은 3상태 그대로 보여준다.
- 노선 상세는 경유 정류장을 **정차 순서대로** 보여준다. 노선도 이미지는 넣지 않는다(금지).
- 문의처 탭은 `AppReport` 안의 안내 화면을 컴포넌트로 추출해 **같은 코드**를 쓴다.

## 6. 완료 기준

- `npx tsc --noEmit` 오류 0
- `npx vitest run` 전부 통과 (새 기능마다 테스트 추가)
- `npx vite build` 성공
- 320×461px에서 홈과 각 탭 첫 화면에 가로 스크롤 없음, 홈 세로 스크롤 없음
- 새 의존성 추가 없음 (아이콘은 기존 `lucide-react`)
- 시설 표기에 `있음/없음/미확인` 외 표현 없음
- `민원 접수` 문구 없음

## 7. 다음 단계 (이 계획 밖)

1. 운행시간표 원본 확보 — 춘천시 요청 또는 공공데이터포털 확인
2. `TAGO_KEY` 설정 후 실시간 버스 위치
3. 정류장 제보 → 공식 민원 접수 연계 (이게 되어야 `민원 접수` 표기가 가능해진다)
4. 대시보드 통합 인박스 — 제보·불편·분실물·문의를 관리번호 단위로 묶기
