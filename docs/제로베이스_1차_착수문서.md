# 쉼표 정류장 — 제로베이스 1차 착수문서

> 버전 1.0 · 2026-07-25  
> 용도: 이 문서 하나로 제품 범위, 필수 데이터, 외부 API, 화면 골조, 기술 골조와 1차 완료 기준을 합의한다.  
> 한계: 실제 구현에는 이 문서를 기준으로 OpenAPI, DB 스키마, 화면 설계서, 테스트 명세를 후속 산출물로 만든다.

## 1. 한눈에 보는 제품

### 한 문장

**춘천 시민이 출발 장소와 목적지를 입력하면 탈 정류장·방면·버스 도착시간을 알려주고, 정류장 상태 제보를 행정 검수와 시설 정보 갱신으로 연결하는 서비스다.**

### 사용자와 가치

| 사용자 | 해결할 문제 | 제품이 주는 답 |
|---|---|---|
| 시민, 특히 고령 이용자 | 어느 정류장에서 어느 방향 버스를 타야 하는지 어렵다. | 탈 정류장·방면·가장 빠른 실시간 도착정보를 짧게 보여준다. |
| 춘천시 담당자 | 시설 현황과 시민 불편 신호가 흩어져 있다. | 제보를 정류장 단위로 묶어 검수·현장확인·갱신한다. |

### 핵심 흐름

```text
시민: 출발·목적 입력 → 장소 확인 → 경로 탐색 → 탈 정류장·방면·도착시간 → 즐겨찾기/상태 알리기

행정: 시민 제보 → AI 분류·중복 후보 → 담당자 검수 → 현장 확인 → 시설 상태 갱신
```

### 1차 범위

| P0 — 반드시 구현 | P1 — P0 뒤에 구현 | 제외 |
|---|---|---|
| 장소 검색·지도 확인 | 즐겨찾기 동기화 | 제보량을 실제 수요로 해석 |
| 대중교통 경로 탐색 | 음성 입력 | AI의 시설 상태 자동 확정 |
| 승하차 정류장·방면 표시 | 정류장 상태 제보·사진 | 근거 없는 도착시간 생성 |
| TAGO 실시간 도착정보 | 관리자 제보 처리 | 공식 연계 전 `민원 접수` 표현 |
| 정류장 시설 3상태 표시 | AI 분류·중복 후보 | 검증되지 않은 예산·설치 자동 결정 |
| 실패 상태의 정직한 안내 | 데이터 승인·롤백 | 시민 계정·소셜 기능 |

## 2. 화면 골조 스토리보드

### 2.1 설치형 시민 앱

| ID | 화면 | 핵심 정보 | 주 행동 | 다음 |
|---|---|---|---|---|
| C0 | 홈 | `버스`, `정류장`, 즐겨찾기 | 버스 조회 선택 | C1 |
| C1 | 장소 입력 | 출발지·목적지, 음성 보조 | 두 장소 검색 | C2 |
| C2 | 장소 확인 | 장소명·주소·지도 핀 | `이 위치가 맞아요` | C3 |
| C3 | 버스 결과 | 도착시간 → 버스번호 → 탈 정류장·방면 → 도보시간 → 조회시각 | 즐겨찾기 또는 상태 알리기 | C0/C4 |
| C4 | 정류장 확인 | 정류장명·4자리 번호·방면·근처 후보 | 대상 정류장 확정 | C5 |
| C5 | 상태 선택 | 시설·불편 유형, 설명, 선택 사진 | 내용 검토 후 제출 | C6 |
| C6 | 접수 완료 | 접수번호·접수시각·처리상태 확인 방법 | 홈으로 | C0 |

결과 화면에는 **가장 빠른 이용 가능 후보와 다음 후보, 최대 2개만** 먼저 보여준다.

### 2.2 공통 QR

| ID | 화면 | 흐름 |
|---|---|---|
| Q0 | 할 일 선택 | `버스 도착시간 확인` / `정류장 상태 알리기` |
| Q1 | 정류장 확인 | QR 정류장 또는 현재 위치 주변 정류장을 번호·방면으로 재확인 |
| Q2A | 버스 조회 | 목적지 입력 → 경로·실시간 도착 결과 |
| Q2B | 상태 알리기 | 상태 선택 → 내용 확인 → 접수 완료 |

QR 값만으로 정류장을 확정하지 않는다. 폐지·이설·훼손 QR 가능성을 고려해 사용자에게 번호와 방면을 보여준다.

### 2.3 관리자 웹

| ID | 화면 | 핵심 행동 |
|---|---|---|
| A0 | 기관 로그인 | SSO·MFA 인증 |
| A1 | 업무함 | 신규·검토중·현장확인·완료 제보 필터 |
| A2 | 제보 상세 | 원문·사진·AI 후보·유사 제보·정류장 확인 |
| A3 | 처리 | 담당 지정 → 자료 대조 → 현장확인 요청 → 결과 기록 |
| A4 | 시설·ID 검수 | 시설 3상태 또는 외부 ID 매핑 승인 |
| A5 | 이력 | 변경 전후 값·작업자·시각·사유 확인 |

### 2.4 공통 실패 화면

| 상황 | 사용자 표시 | 금지 |
|---|---|---|
| 장소 없음 | 입력 유지 + `검색 결과가 없어요` | 임의 장소 선택 |
| 춘천 밖 | `춘천 안의 장소를 선택해주세요` | 가장 가까운 춘천 좌표로 보정 |
| 경로 없음 | `이 위치에서 갈 수 있는 버스를 찾지 못했어요` | 가까운 정류장 임의 추천 |
| 실시간 실패 | `실시간 도착정보를 불러오지 못했어요` | 배차간격을 도착시간처럼 표시 |
| ID 불일치 | 결과 결합 중단 + 내부 검수 큐 | 이름만으로 TAGO 결과 결합 |
| 제보 저장 실패 | 재시도·입력 유지 | 접수 완료 표시 |

## 3. 필요한 데이터

### 3.1 반드시 있어야 하는 데이터

| 데이터 | 필수 필드 | 기준 출처 | 쓰임 |
|---|---|---|---|
| 정류장 마스터 | `management_id`, 표지판 번호, 이름, 좌표, 방면, 운영상태, 유효기간 | 춘천시 공식 정류장 자료 | 모든 데이터의 기준 |
| 노선 마스터 | 내부·외부 노선 ID, 번호, 방향, 운행상태, 정류장 순서 | 춘천시·TAGO | 경로·방면 검증 |
| 외부 ID 매핑 | 내부 정류장 ID, 공급자, 공급자 정류장 ID, TAGO 노드 ID, 좌표, 방면, 검수상태 | 공식 대응표 + 사람 검수 | 경로와 실시간 도착 결합 |
| 시설 관측 | 정류장 ID, 시설종류, `yes/no/unknown`, 출처, 관측일, 검수자, 유효기간 | 공식 대장·현장조사 | 시민 시설 표시·행정 갱신 |
| 시민 제보 | 접수 ID, 정류장 ID, 유형, 원문, 첨부키, 상태, 처리이력 | 시민 입력·관리자 처리 | 행정 업무 |
| 데이터 버전 | 원본 기준일, 체크섬, 빌드 ID, 승인·배포시각, 이전 버전 | 데이터 파이프라인 | 변경 추적·롤백 |

### 3.2 있으면 좋은 행정 데이터

| 데이터 | 용도 | 주의 |
|---|---|---|
| 시간대별 승하차 | 현장조사 참고 | 정류장 ID 직접 매핑이 확인된 값만 사용 |
| 병원·시장·복지시설 POI | 생활권 참고 | 실제 이용자 속성으로 단정 금지 |
| 시설 설치·보수 이력과 단가 | 예산 검토 | 최신 계약·회계 근거 필요 |
| 시민 제보 집계 | 반복 불편 탐지 | 승차량·수혜인원으로 표현 금지 |

### 3.3 현재 확보된 기반

| 항목 | 현재 값 | 남은 일 |
|---|---:|---|
| 정류장 | 1,890개 | 방면·운영상태·유효기간 보강 |
| TAGO 노드 매핑 | 1,845개 | 미매핑 45개 원인 분류·검수 |
| 노선 연결 정류장 | 1,853개 | 미연결 37개 원인 분류 |
| 노선 | 223개 | 방향·운행 계통 현행 검증 |
| 노선-정류장 참조 | 16,168건 | 공급자 응답과 대표 노선 대조 |

현재 원본 범주:

- 정류장 위치·정류장별 노선
- TAGO 정류장·노선과 내부 ID 대응 자료
- 시간대별 승하차
- 벤치·그늘막·가로등·버스정보안내단말기
- 시설 현황조사·이미지 라벨링·로드뷰 조사 양식

### 3.4 절대 데이터 규칙

```text
management_id = 내부 정류장 기본키
stop_no        = 현장 표지판 번호
tago_node_id   = TAGO 실시간 조회 키
provider_id    = 경로 API 정류장 키
```

- 정류장명과 버스번호는 기본키가 아니다.
- 시설은 `yes | no | unknown`만 사용한다.
- 근거가 없으면 `unknown`이며 `no`가 아니다.
- 외부 ID는 `verified | inferred | unresolved`로 관리한다.
- 운영 경로·도착 결합에는 `verified`만 사용한다.
- 시민 제보와 AI 결과는 사실 확정 자료가 아니다.

## 4. 사용할 외부 API

### 4.1 최종 권장 조합

| 역할 | 1차 선택 | 선택 이유 | 운영 조건 |
|---|---|---|---|
| 장소 검색·주소·지도 | [카카오맵 API](https://developers.kakao.com/docs/ko/kakaomap/common) | 국내 장소와 지도 SDK를 한 공급자로 통일 | 도메인 등록, 쿼터·과금 확인 |
| 대중교통 경로 | [ODsay 대중교통 길찾기 v1.8](https://lab.odsay.com/guide/releaseReference?platform=web) | 정류장 ID·좌표·지역 Local ID를 제공해 TAGO 매핑에 유리 | 춘천 대표 경로 10건과 상업 이용 조건 확인 |
| 실시간 도착 | [TAGO 버스도착정보](https://www.data.go.kr/data/15098530/openapi.do) | 노드 ID 기준 도착 초·이전 정류장 수 제공 | 서버 프록시, 10~20초 캐시 |
| 정류장 갱신·대조 | [TAGO 버스정류소정보](https://www.data.go.kr/data/15098534/openapi.do) | 정류장 공식 외부 ID·기본정보 대조 | 변경 diff 후 사람 승인 |
| 노선 갱신·대조 | [TAGO 버스노선정보](https://www.data.go.kr/data/15098529/openapi.do) | 노선 ID·운행정보 대조 | 내부 노선 ID와 별도 관리 |
| 도보 경로 | [카카오맵 도보 경로 API](https://developers.kakao.com/docs/ko/kakaomap/rest-api) | 장소·지도와 같은 좌표·공급자 사용 | 서버 호출, 실보행 검증 |
| 음성 입력 | 브라우저 Web Speech | 입력 보조 기능에 충분 | 미지원·권한거부 시 직접 입력 |
| 사진 저장 | S3 호환 객체 스토리지 | DB와 파일 분리, 만료 URL 사용 | MIME·용량·악성파일 검사 |
| 관리자 인증 | 기관 SSO(OIDC/SAML)+MFA | 계정 회수와 역할 관리 | 춘천시 인증환경 확인 |

### 4.2 API 선택 판단

카카오맵도 대중교통 경로를 제공하지만 현재 공개 응답 명세의 정류장 정보는 이름 중심이다. 쉼표 정류장은 경로 정류장을 내부 `management_id`와 TAGO `nodeId`에 정확히 연결해야 하므로 **ODsay를 1차 경로 공급자로 선택한다.** 카카오 대중교통 API는 안정적인 정류장 ID·방면 제공이 실응답으로 확인된 뒤 대체 후보로 검토한다.

### 4.3 키 보관

| 키 | 위치 |
|---|---|
| 카카오 JavaScript 키 | 시민 앱에 공개 가능하나 허용 도메인 제한 |
| 카카오 REST 키 | 서버 비밀 저장소 |
| ODsay API 키 | 서버 비밀 저장소 |
| 공공데이터포털 서비스 키 | 서버 비밀 저장소 |
| 객체 스토리지 비밀키 | 서버 비밀 저장소 |

`VITE_` 변수는 브라우저 번들에 공개되므로 서버용 비밀키를 넣지 않는다.

## 5. 서비스 API 골조

### 시민 API

| 메서드 | 경로 | 역할 |
|---|---|---|
| `GET` | `/v1/places/search?q=` | 춘천시 장소 후보 |
| `POST` | `/v1/trips/search` | 승하차 정류장·노선·방면·도보 구간 |
| `GET` | `/v1/stops/{id}` | 정류장·시설·근거 |
| `GET` | `/v1/stops/{id}/arrivals` | 목적지행 노선의 실시간 도착 |
| `POST` | `/v1/report-uploads` | 만료 업로드 URL |
| `POST` | `/v1/reports` | 상태 제보 접수 |
| `GET` | `/v1/reports/{token}` | 제보 처리 상태 |

### 관리자 API

| 메서드 | 경로 | 역할 |
|---|---|---|
| `GET` | `/api/reports` | 업무 목록 |
| `GET` | `/api/reports/{id}` | 원문·첨부·이력 |
| `PATCH` | `/api/reports/{id}/status` | 상태·담당 변경 |
| `POST` | `/api/stop-mappings/{id}/verify` | 외부 ID 승인 |
| `POST` | `/api/facilities/{id}/observations` | 시설 관측 등록 |
| `POST` | `/api/data-imports/{id}/approve` | 데이터 배포 승인 |
| `GET` | `/api/audit-logs` | 열람·변경 감사 |

### 경로 계산 규칙

```text
1. 카카오 장소 검색 → 사용자가 출발·목적 좌표 확정
2. ODsay 경로 탐색 → 승하차 정류장·노선·방면 후보
3. 공급자 정류장 ID → verified management_id로 변환
4. 승차 정류장의 TAGO nodeId로 노선별 실시간 도착 조회
5. 도착시간 > 실제 도보시간 + 안전여유시간인 후보만 유지
6. 직행 우선 → 실제 이용 가능 시각 우선 → 도보 짧은 순으로 정렬
7. 상위 2개 표시
```

경로 응답과 실시간 도착 응답은 캐시 주기가 다르므로 분리한다.

### 배포 분리


시민 앱과 관리자 웹은 도메인, 배포 계정, 서비스 워커, API·DB 권한을 분리한다.

## 7. 디자인·사용성 기준

- 1차 사용자: 복잡한 조작과 스크롤이 어려운 고령 이용자
- 기준 화면: 실제 사용영역 320×461px
- 핵심 흐름: 세로 스크롤 없이 한 화면 한 행동
- 주요 터치 영역: 48px 이상
- 결과 정보 순서: 도착시간 → 버스번호 → 정류장·방면 → 도보시간 → 조회시각
- 상태는 색만으로 표현하지 않음
- 음성 입력은 보조이며 모든 기능을 직접 입력으로 수행 가능
- 200% 확대, 스크린리더, 키보드, iOS·Android 안전영역 검증
- 브랜드색: 춘천 PANTONE 299C 근사 `#00A3E0`
- 기본 글꼴: 나눔고딕, 기본 글자색 `#333333`

## 8. 보안·운영 최소 기준

- 외부 REST API 키는 서버에서만 사용한다.
- 관리자 인증은 기관 계정·MFA·역할 권한을 적용한다.
- 관리자 열람·변경·내보내기는 변경 불가능한 감사 로그를 남긴다.
- GPS는 경로 계산 후 장기 저장하지 않는다.
- 목적지 상세 검색어와 음성 원본은 기본적으로 보관하지 않는다.
- 제보 원문의 전화번호·주소·얼굴·차량번호를 마스킹한다.
- 업로드는 확장자·MIME·용량·악성파일을 검사한다.
- 장소·경로·도착 API의 오류율, 지연, 호출량과 매핑 실패를 모니터링한다.
- 원본 데이터 변경은 diff·품질검사·사람 승인 후 배포하고 롤백 가능해야 한다.
